## Decisions in force

- D1 Require the goal and next step at open; make criteria optional: Swap them. The close gate already returns no-criteria when no un-struck criterion remains, and the stored schema already permits an empty array, so the constraint is not removed: it moves from the one moment that cannot satisfy it honestly to every moment that can. Assertion R-8 asks about the definition of done at every stop. Reverses the minItems 1 ruling shipped in ce2ef720.
- D2 Recording splits by who holds the material, never by who holds the tools: Split by knowledge. The subagent carries six assertions covering what it established, what it tried and abandoned, what faults it observed, what files it produced, where it stopped and what it could not determine. The main thread carries four covering selection between options no subagent saw, the definition of done, the next action, and a sweep for what a subagent could not record. Restates the rule already shipped in the server instructions.
- D3 Gate text is model-checked assertions, never machine-checked invariants: Their own section, R-1 through R-10, with invariant S11 forbidding any of them from appearing in an A, O or S table. They are written as asserted states rather than questions, so they invite a check rather than an answer, applying the goal model rule that a goal is a state and never a task. Two shapes are banned in an assertion: grading the model's own earlier output, and inviting speculation about what could go wrong rather than naming what was observed.
- D4 The recording gate takes its baseline at SessionStart, not at resume: The baseline moves to the SessionStart hook and resume_thread stops writing it. SessionStart is the earliest point in a session and already bound in hooks/hooks.json, its payload is a captured fixture, and the state directory helper the gate uses is already wired, so the move costs one call site rather than new machinery. Writing at open_thread was rejected because it covers only the session that opens a thread and leaves a session that resumes an existing one and records before resuming exactly as blind as today. Leaving resume_thread as a second writer was rejected because it overwrites whatever SessionStart recorded and reinstates the fault. Two consequences the implementer inherits: the test at :387-404 inverts rather than being added to, since a write landing before the resume now clears the gate, and a session whose SessionStart hook did not run has no baseline and the gate stays silent, which is the fail-open behaviour the spec already requires.
- D5 Gate damping reads prompt_id from the payload, never the transcript: Damping compares prompt_id. The field is declared on the Stop payload at test/fixtures/hook-types.d.ts:66 and carries a real value in the captured stop.json fixture, so it is verified rather than inferred, and a different prompt_id since the last fire is exactly one fresh human turn. It costs no transcript pass at all, which matters because the gate is about to fire far more often than it does today. Two edits fall out: hooks/stop.ts:14-19 currently discards prompt_id and must forward it, and the StopEvent type at src/hooklib/stop-gate.ts:40-45 must carry it. The transcript route stays available if a future need forces it, but it would first need a captured transcript fixture and coverage for the branch that reads one.
- D6 The Stop gate advances its reference head on a silent turn too: The head is written on the clearing path as well as at the fire, and the spec is not amended, because nothing in it needs amending. The invariant says that after a fire the gate is cleared when the head moves off the value recorded at that fire, and that stays exactly true; it simply says nothing about what the reference becomes afterwards, and this fills that gap rather than contradicting it. With the change the reference is the head at the end of the previous turn, so each turn is judged on whether anything reached the ledger during it, which is what continuous recording means and what makes the damping reachable. The cost is that the gate writes state on a silent verdict, which it never does today, and that write must not touch the fire count or the recorded prompt id or it would reset the damping every quiet turn. Shipping as written was rejected because it reproduces the exact defect this work removes, with more text attached.
- D7 S7 governs the close decision, not every file that reaches the gate: close_thread is admitted to the file census with O9 named as its reason, separate from the existing A16 admission which covers the create and insert paths. The spec text is decisive: S7 says the done gate contains no branch that reads settledness, and the done gate is src/domain/done-gate.ts, not every file that transitively reaches it. The census's own failure message says it polices files that decide or refuse on the gate verdict, which is the right intent; its implementation matches identifiers anywhere in a file and so catches reporting as well as deciding. Reverting the split was rejected because O9 is an invariant of the same spec and the split is the aggregation guard the spec relies on in place of refusing to close. Narrowing the boundary to two files was rejected because it would stop catching a settledness branch introduced in the tool layer, which is a real way to break S7. The teeth are preserved by asserting behaviourally that no settledness value can cause a close to be refused, which is what O9 promises in words when it says no count is ever a reason to refuse.
- D8 Keep the one-shot marker and refuse a SubagentStop whose agent_type is empty: Option three. Keep the one-shot-per-agent marker, reject stop_hook_active, and refuse an event whose agent_type is empty. It is the only option that addresses what the capture actually falsified, since the spec's real error was the premise that a SubagentStop event means a subagent finished. The test is pure in-payload with measured 100 percent agreement against the SubagentStart join over 10,008 rows, and refusing on it matches the discipline already in the same function, where an unusable agent_id returns silent rather than firing blind. It also fixes the marker directory's unbounded growth as a side effect, since a refused event writes no marker, cutting roughly 10,000 empty files a month to about 2,000. stop_hook_active is rejected on failure direction: if it is session-scoped rather than subagent-scoped, a subagent stopping while the main thread is mid-continuation is silenced without ever being asked and its material is lost with nothing recording that, whereas the marker is written only when the gate actually fired and a failed write exits non-blocking. What is given up: agent_type becomes load-bearing for a purpose the spec never named, and a real subagent whose type is legitimately empty, a plugin-scoped or custom agent whose name resolves to nothing, would be skipped. That failure is silence, the direction the gate already fails. Option four is revisitable the day the documentation states that the flag at SubagentStop reflects that subagent's own continuation; that sentence is the trigger. The guard must land no later than the binding, because binding without it ships the defect.
- D9 Every dispatched subagent is asked to record; another agent's write never silences it: Ask every dispatched subagent independently. The human's statement of intent, which governs: each dispatched subagent holds the context and information of the work it did and the decisions it made, and it is asked to update the store with what it holds. If that information is already present, nothing is added. If something crucial for a future agent to understand a decision or continue the work is missing, it is added. This has nothing to do with other agents recording information from their own sessions, and it never should. The session-wide head-movement check therefore contradicts the gate's purpose and is a defect in merged code rather than a design choice to preserve. The per-agent marker already keys on the right thing, the pair of session id and agent id, so the fix is to stop letting a session-wide ledger movement stand the gate down, not to change what the marker records. Scoped as its own unit after the binding lands, because the binding is already in flight and the gate under-fires rather than misfires while this stands.
- D10 Keep the refusal on moving a done criterion to unsettled; make the relay's remedy real instead: Keep the refusal. The human ruled that A13 and C-4 are the governing intent and that the refusal preserves them, so the over-broad text in A16 and B56 is what needs correcting rather than the code. No existing refusal is deleted or weakened. The relay is repaired at the other end instead: the amend_criteria rewrite is made to carry check, so the remedy the refusal already names becomes real. The precedent sitting beside it supports this shape, since amend_criteria.ts:189-194 refuses settledness and settled_by on a rewrite specifically because accepting them there would drop them silently, and check was given no such guard and is dropped in exactly that way. Refusing check as its siblings are refused was left open to the implementing unit as the alternative, weighted against the fact that a refusal would leave the relay with no remedy at all. Consequence for the second erratum batch: the A16 and B56 text becomes a SPEC-ERROR entry describing code that is stricter than the spec says, which relaxes no requirement.
- D11 Name the two ledger tools individually rather than taking the server wildcard: Keep the two named tools. The wildcard is smaller and would survive Logbook adding tools, and it is nonetheless the wrong choice, because it grants ALL TWELVE ledger tools rather than two. That directly contradicts decision 01M1X4CVDH6NQMFPMHG6934197, which withholds update_thread from subagents on the ground that it carries next_step, active_goal and risk retirement alongside the fields a subagent would want, and that an MCP call carries no caller identity so a wide grant cannot be narrowed server-side. A server wildcard would also hand a subagent open_thread, close_thread and park_thread, every thread lifecycle tool the spec excludes. The cost accepted in exchange is that the grant is a hand-maintained pair of tokens in thirteen files that will not automatically pick up a future tool, which is the correct direction to fail: a new tool stays ungranted until someone decides it should be, rather than arriving silently. The third option is unavailable on the evidence rather than rejected on the merits, since mcpServers connects a server without granting its tools. Note for a later reader: the smallness argument will recur, and the answer is that the grant's narrowness is the point, not an accident of how it was written.
- D12 Grant subagents the whole ledger surface; the write-time gate is the protection: Reverse it. Grant mcp__plugin_logbook_ledger__* per agent, the trailing glob form rather than the bare server name, which is the form witnessed working against a plugin MCP server. One token covers every present and future tool, so no later round is needed when a tool is added. A grant was never capable of being the protection: close_thread already refuses unless every un-struck criterion is done and a closing statement exists, and that refusal fires against every caller. The narrowing was a second and weaker copy of an invariant that was already correctly implemented one layer down. What this gives up is real and is accepted: the wildcard widens rather than narrows the set of principals who can write to the shared record, including researcher, which reads untrusted web pages.
- D13 Do not split the recording tools onto a second MCP server key: Do not split. The split's only advantage over a plain server wildcard was an incapability that is now unwanted, so nothing remains to justify a second process, a rewrite of the packaging check that refuses any configuration not declaring exactly one server named ledger at scripts/check-packaging.mjs:241-243, and a repair to the skills contract test whose census would throw when log_session_event left the single listing. Two findings from the feasibility work are kept because they are true independently: the recording pair are the only two write tools touching neither the session pointer nor rt.sessionId, and test/contract/matcher.test.ts:41-44 would stay green while asserting a name production no longer used, which is a live weakness in the suite regardless of this decision.
- D14 An attestation records the proof that produced it, never a label the caller picked: Take the third. Three rules govern every attestation field from here. One: it is never satisfiable by choosing a label; it requires a particular that only doing the work produces, which is the owner's existing pr-create ruling that a verification result is a number or a state and never an adjective. Two: the proving step is itself recorded, so a later reader confronting a passing claim can answer what the model did to convince itself, and what it did not check. Three: Logbook stores both verbatim and grades neither. The mechanism is not prevention. A fabricated label is traceless and a fabricated particular is falsifiable, so the gain is that a wrong record becomes catchable rather than impossible. The case this actually catches is the sincere model that believes it verified and did not, which is the common one; deliberate fabrication is unaffected and that is accepted. settled_by is already built this way and is the only field the audit found honest, so the rule is not new to the codebase, only ungeneralised. The residual risk is ritual: an invariant asked too often is answered on autopilot. The defence is the same rule, since fluent prose can be produced without looking and a specific value cannot.U+003C/outcome>U+000AU+003Cparameter name="scope">attestation contract
- D15 Refuse rewriting a criterion already marked done, and drop the check snapshot it made necessary: Refuse it. A rewrite on a done criterion joins the existing struck guard as a structural refusal in the same shape and the same refusal grammar. The check is then stable from mark-done forward by construction, so the proof entry no longer carries a check snapshot and shrinks to the criterion id, the supplied branch value and the counterfactual. This is a breaking change: a call that previously succeeded now refuses, which is the point. It costs the case where an author wants to reword a done criterion's check without reopening it; that case is served by striking and inserting, which is the succession path the spec already prefers at 2026-09-06-continuity-recording-model.md:256. Also settled here on the owner's delegation: the criteria-writers census auto-classifies any pattern-bearing free-text leaf as allowed without a disposition entry at criteria-writers.test.ts:95, which is how settled_by escaped the table. A format pattern proves a string is non-blank and proves nothing about whether the field belongs, so the auto-classify branch is removed and every free-text leaf is classified explicitly, in line with the standing rule that a census halts on the unclassifiable rather than growing an escape hatch.
