## Open risks

- R1 This repo's ledger is one project with one user, holding records only since the 2026-09-04 wipe. Measurements from it can show that a failure happens but cannot set a number for every project, which is the fault the principle names; the 65,536-byte record cap was 1.68 times one project's largest record.
- R2 Most external citations in section 7 of the audit rest on the research agents' own reading of 2026 sources that postdate the model's knowledge. Only three load-bearing papers were re-fetched and checked in this session (Handoff Debt arXiv 2606.02875, DreamBench-SWE arXiv 2608.20664, Gavel arXiv 2601.04424); one researcher claim about DreamBench-SWE was dropped because its abstract does not state it. Bears on c5.
- R3 hooks/lib/io.ts cuts every hook output string at 14,000 graphemes with no marker, above Claude Code's documented 10,000-character hook limit, past which the host moves the text to a file and shows a preview. Three real hand-off briefings in this ledger exceed 14,000 characters (14,468, 16,174 and 35,519, audit section 6.1). The stop hook's verbatim gate embeds the whole briefing in its block message, so those tails would vanish without a sign. Bears on c6.
- R4 The full-record view at logbook://thread/{id} lists every artifact, retired ones included, with no retired marker, so a reader sees a retired pointer as live; for example, artifact 01M2MQ40E0XB01TCAA61BH08DT still shows the old register path there. The briefing filters retired artifacts, but the full view, which the briefing names as the complete record, does not. Bears on c6.
- R5 The host behaviour the first audit's R1, R7 and R13 and this thread's secondary report rely on was read from Claude Code 2.1.273's own code and docs, not observed in a live run: a declared maxResultSizeChars skips the token check for structuredContent results; field descriptions are not cut at 2,048; text blocks are dropped when structuredContent is present; PreToolUse context reaches the model beside the tool result. A later Claude Code version, or a remote flag the program fetches, can change any of these. A sign it has happened: a briefing arrives as a file path or a preview, or a hook's text arrives before the tool runs.
- R6 External claims that the secondary report (docs/audits/2026-09-16-capture-and-retrieval-audit.md) marks "not re-checked here" rest on the research agents' own reading of their sources, many of them from 2026, after the model's knowledge. The main session and a fact-check agent confirmed the load-bearing ones against saved copies: Vercel, RetrievalQA, Blair and Maron, LIMIT, Sen et al., Rath et al., Xie et al., the Rakha thesis, the Mem0 migration guide, Furnas, Gloaguen et al. and the Cursor forum. The rest are unconfirmed. A sign one is wrong: its source, when opened, does not state the figure or quote. Bears on c8.
- R7 Pre-mortem, as named by the human: sessions may fill the next step's records list lazily, stating an empty list or naming the wrong records, so that nothing improves. The prototype must be graded on whether the named list contains the record the step needed, not only on whether the session looked, and the tasks must include a ruling that names no file, so the file-name match cannot rescue a lazy list.
- R8 Pre-mortem, as named by the human: a briefing centred on the next step may miss something the step needed, and the session then acts without it. Leaving out one needed item costs far more than the noise that scoping removes (tau-bench: 33.2 to 10.8). The proof must count misses directly, with a task whose needed record the writer did not name.
- R9 Pre-mortem, as named by the human: the change may add too much ceremony, because every step change now needs a lookup, and sessions may become slower or wordier. The proof must compare tokens and tool calls per task between today's logbook and the prototype against a ceiling fixed in advance.
- R10 Pre-mortem, as named by the human: the proof may cost more than the problem is worth. A three-run pilot prices a run first, the human sets a hard cost ceiling (claude plugin eval --max-cost-usd) before the full runs, and the task set is kept to the smallest that still decides: about 10 tasks with 3 runs each per version.
- R11 Deferred review finding: resume_thread now indexes every thread, and readAllRecordFiles rethrows any error but not-found, so an unreadable session directory on another thread fails a resume after the pointer was already written (reproduced with chmod 000). Fix later by counting such a directory as unreadable records or rendering before writing the pointer.
- R12 Deferred review finding: the Stop hook's gate and the write guard take the project from the hook event's cwd, which follows a Bash cd; the file trigger now prefers CLAUDE_PROJECT_DIR, but the stop gate and guard do not.
- R13 Deferred review finding: the helper and helper-read-only proof cases grade the parent's last message, which can pass without the helper's report arriving, because the parent can grep src itself; grade the Agent tool_result instead once its trace shape is confirmed.
- R14 Deferred review finding: previousSessionEntries, clipWithMarkerFloor and clipGraphemesFloor have no production caller after the step-centred briefing; remove them with their unit tests in a later pass.
